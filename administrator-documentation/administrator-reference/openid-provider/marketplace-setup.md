# NexPort Marketplace SSO Setup (OpenID Applications)

Use this guide to configure a NexPort Marketplace instance to sign users in with NexPort as the OpenID Connect (OIDC) provider. This ensures Marketplace uses the same trusted login experience, permissions, and org scoping rules as the rest of NexPort.

## Before You Start

Collect the following information from the NexPort Marketplace team so the NexPort app configuration can match the Marketplace instance:

- NexPort Marketplace instance name and environment (dev/qa/prod).
- OIDC redirect URI(s) for the instance.
- NexPort Marketplace storefront URL (for the campus link).
- Whether the NexPort Marketplace instance should create users in NexPort.

> Note
> Each NexPort Marketplace instance needs its own OpenID Application. Redirect URIs are instance-specific so NexPort only returns users to the correct Marketplace instance.

## Create the NexPort Marketplace OpenID Application

The OpenID Application is the contract between NexPort (IdP) and the Marketplace instance (client). It defines which org the Marketplace can access, where NexPort is allowed to redirect users, and which claims/scopes can be issued.

1. Open **Administration** → **OpenID Applications**.
2. Select **Create**.
3. Set the **Organization** to the NexPort Marketplace root organization. This anchors the Marketplace app to the correct org tree for permissions and data access.
4. Set **App Type** to **Marketplace**.
5. Enter the **Client ID** and **Client Secret** (generated by NexPort or the NexPort Marketplace team).
6. Add the **Redirect URIs** (one per line). These must match the Marketplace instance callback URLs exactly or sign-in will fail.
7. Enable the required access:
   - **Allow SSO** (required for login)
   - **Allow API Access** (required for NexPort Marketplace APIs)
   - **Allow Profile Access** (enable when NexPort Marketplace needs profile claims)
   - **Allow Create User** (only if NexPort Marketplace should provision users)
8. Leave **Mandatory** off unless the app must be non-revocable.
9. Select **Save**.

## Integration Steps for the Commerce Team

These steps ensure the commerce-side configuration matches the NexPort app settings above so the OIDC handshake succeeds and the Marketplace receives the right claims.

Use this checklist to complete the NexPort Marketplace OIDC client setup on the commerce side:

1. Use the NexPort OIDC discovery document to configure endpoints (authority, authorization, token, and end-session). This avoids hard-coding URLs and ensures environment parity.
2. Configure the client ID and client secret to match the NexPort Marketplace OpenID Application.
3. Ensure the redirect URI(s) exactly match what is configured in NexPort. Mismatches are the most common cause of login failures.
4. Request only the scopes required for the integration (commonly `openid`, `profile`, `email`, plus API scopes as needed). This keeps tokens minimal and aligns with NexPort permission gates.
5. Complete a login flow and confirm the returned claims match expected user data.

## Logout and Session Management Guidance

Marketplace and NexPort manage separate sessions. Logouts must clear both sides to prevent stale tokens or confusing “still signed in” states.

- Register a **Post-Logout Redirect URI** in the NexPort Marketplace OpenID Application if the commerce app uses OIDC end-session.
- Use the end-session endpoint from the discovery document to sign the user out of NexPort.
- Ensure the commerce app clears its own session and tokens after logout completes.

## Add the NexPort Marketplace Link (Optional)

This replaces “Find More Training” with a direct Marketplace link so learners have a consistent entry point into the Marketplace storefront.

To replace **Find More Training** with a Marketplace link:

1. Edit the NexPort Marketplace OpenID Application.
2. Enable **Campus Marketplace Link**.
3. Enter the **Campus Marketplace Link URL** (storefront URL).
4. Save the application.

## Assign Permissions to the NexPort Marketplace App

Marketplace access is controlled through app grants. Without app grants, tokens can be issued but API access will still be denied.

Marketplace access is enforced through app grants:

1. Open **Administration** → **Permissions**.
2. Select the NexPort Marketplace app as the target.
3. Assign the role(s) that grant access to the root organization.

App grants cascade down the organization tree, so root-level assignment is sufficient.

## Validation Checklist

- Marketplace login redirects to NexPort and returns to the configured callback URL.
- The NexPort Marketplace app can access required APIs for the mapped org tree.
- The campus link opens the correct Marketplace storefront.
